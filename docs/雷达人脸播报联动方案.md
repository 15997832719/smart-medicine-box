# 雷达、人脸、SYN6288 与小智音箱联动方案

## 目标

1. LD2410C 检测到有人靠近。
2. 香橙派摄像头抓取多帧并识别人脸。
3. 按识别出的用户查询其个人用药计划：
   - 老人：老人自己的用药计划。
   - 子女：子女药箱/用药计划。
   - 未识别：不播报任何个人用药信息。
4. 小智音箱正在对话时，禁止 SYN6288 插话；待小智空闲后再决定是否播报。

## 模块职责

- ESP32-C3：雷达采样、SYN6288 串口控制、设备状态上报。
- Orange Pi Zero 3：摄像头、人脸检测/识别、联动状态机、网络接口。
- 后端：用户身份、家属关系、用药计划和播报文本。
- 小智服务端：语音唤醒、ASR、对话和 TTS，并提供 idle/listening/speaking 状态。

## 推荐数据流

```text
LD2410C presence
      |
      v
ESP32-C3 --radar event--> Orange Pi coordinator
                              |
                              +--> camera capture + face recognition
                              |         |
                              |         v
                              |    backend: user + medication plan
                              |
                              +--> refusal while Xiaozhi busy
                              +--> wait until idle
                              |
                              v
                       ESP32-C3 --> SYN6288 --> speaker
```

## 统一播报仲裁状态机

```text
IDLE
  radar_presence=true -> CAPTURE_FACE

CAPTURE_FACE
  3~5 frames, face detected
    recognized + score above threshold -> WAIT_FOR_AUDIO_IDLE
    unknown / no face -> DROP_PRIVATE_ANNOUNCEMENT

WAIT_FOR_AUDIO_IDLE
  xiaozhi idle >= 1.5s AND syn6288 idle -> ANNOUNCE
  xiaozhi listening/speaking -> remain queued until TTL (10s)
  TTL expired -> DROP

ANNOUNCE
  send text to SYN6288
  trigger stop if Xiaozhi becomes listening/speaking
  after done -> PRESENCE_COOLDOWN

PRESENCE_COOLDOWN
  same presence episode: never repeat
  after person leaves + cooldown 30~60s -> IDLE
```

## 必须遵守的规则

1. 小智优先级高于提醒播报。
2. 小智进入 listening/speaking 时，立即停止 SYN6288 当前播报并清空待播队列。
3. 雷达只在人进入时触发一次，不按检测帧重复触发。
4. 同一人在场期间最多播报一次；离开后重新进入才允许再次触发。
5. 只有人脸识别置信度达到阈值且匹配到已注册用户时才播报个人用药信息。
6. 未注册/识别失败时只允许通用提示，不泄露任何药品信息。
7. 播报内容由后端数据生成，不在设备端编造药名、剂量或用法。

## 小智忙碌状态获取

优先级从高到低：

1. 在小智服务端增加状态回调/消息发布：`idle`、`listening`、`speaking`。
2. 通过小智 WebSocket 会话生命周期在 Orange Pi 侧推断状态。
3. 最后才使用麦克风 VAD 作为兜底，不作为首选。

## 建议接口

### ESP32 -> Orange Pi

```json
POST /radar/event
{"present": true, "distance_cm": 148}
```

### Orange Pi -> ESP32

```json
POST /tts
{"text": "该吃降压药了，一次一片。", "request_id": "..."}
```

```json
POST /tts/stop
{}
```

### 小智服务端 -> Orange Pi

```json
POST /xiaozhi/state
{"state": "listening"}
```

## 人脸识别实现

- 检测：OpenCV YuNet。
- 识别：OpenCV SFace 本地 embedding。
- 每人采集 5~10 张不同角度、不同光线照片。
- 多帧投票，连续 3 帧一致才确认身份。
- 阈值先使用 SFace 推荐值，再根据现场误识率调整。
- 识别通过后只保存 embedding，不长期保存原始人脸照片。

## 分阶段落地

1. 完成 YuNet 人脸检测并验证画面质量。
2. 注册老人和子女各 5 张人脸，完成本地身份识别。
3. 在后端增加“按用户返回下一次用药播报文本”接口。
4. 在 Orange Pi 实现联动状态机，先用模拟雷达/小智状态测试。
5. 给 ESP32-C3 增加 WiFi 通信，或将 ESP32 接到香橙派串口。
6. 接入小智服务端真实状态，完成端到端测试。
7. 连续运行测试：重复触发、多人同时出现、小智对话中触发、网络断开。

## 当前优先级

先完成人脸检测和两人注册，不急着直接改 SYN6288。身份识别稳定后，再接入播报仲裁，避免把错误药名播给错误的人。

# 最终独立运行与服药视频方案

## 一、不连接电脑也能运行

电脑只用于首次刷机、配置和调试。最终设备由独立电源和 WiFi 运行：

```text
5V/3A 电源 -> Orange Pi -> USB 摄像头
5V/2A 电源 -> ESP32-C3 -> 雷达 + SYN6288

Orange Pi <--WiFi--> ESP32-C3
Orange Pi <--WiFi/WebSocket--> 小智服务
Orange Pi <--互联网--> 后端 -> 手机 App
```

ESP32-C3 最终通过 WiFi 与香橙派通信，不再依赖电脑 USB。这样摄像头可以独占香橙派的 USB-A 接口。必要时也可以使用带供电的 USB HUB，让 ESP32 通过 USB 串口连接香橙派，但 WiFi 方案更简单。

香橙派上的服务需要设置成 systemd 开机自启，断电重启后自动恢复，不需要显示器和键盘。

如果家里没有互联网，本地雷达、人脸、SYN6288 仍可工作；但要上传视频到手机 App，后端和家庭网络必须能访问互联网。

## 二、服药过程录像

推荐流程：

1. 雷达检测到人。
2. 摄像头识别出已登记用户。
3. 播报该用户的下一项用药。
4. 同时开启一段 20～30 秒录像。
5. 在录像结束后保存事件记录。
6. 后端接收视频和事件信息。
7. 手机 App 显示该用户的服药记录和视频。

建议在香橙派内存中维护一个 5 秒环形缓冲，真正触发时把触发前 5 秒也写入视频，避免老人已经开始拿药才启动录像。

## 三、服药动作识别

“手送到嘴边”可以作为辅助判断，但单独使用容易误判，例如喝水、擦嘴、吃东西都会被识别成服药。

建议把结果分成三档：

```text
possible_taken   检测到疑似服药动作，等待确认
confirmed        老人语音确认或家属 App 确认
not_confirmed    超过时间没有确认
```

第一版最稳妥的做法：

- 识别到人后自动录像
- 用轻量动作模型标记“疑似服药”
- 通过小智或 App 问一句“您已经吃药了吗？”
- 老人确认后再把记录标记为“已服药”

动作识别不能单独作为医疗事实。录像、动作置信度和用户确认要一起保存。

## 四、小智与播报的冲突处理

- 小智 `listening` 或 `speaking` 时，SYN6288 不得开始播报。
- 小智开始对话时，立即向 SYN6288 发送停止命令，并取消待播内容。
- 雷达提醒队列最多等待 10 秒，超时丢弃，不补播。
- 录像可以继续，但建议录制无音频视频，避免把老人和小智的私人对话录进去。
- 同一次人在场最多提醒一次；离开后经过冷却时间才允许下一次。

## 五、后端和 App 需要新增

后端新增服药事件表，例如：

```text
id
user_id
reminder_id
started_at
ended_at
status                  possible_taken / confirmed / not_confirmed
action_confidence
video_url
thumbnail_url
created_at
```

新增接口：

```text
POST /intake-events          上传事件和视频
GET  /intake-events          家属查看服药记录
POST /intake-events/{id}/confirm  确认已服药
```

视频建议存储到对象存储，数据库只保存 URL 和元数据。手机 App 的“最近服药记录”增加：

- 视频缩略图
- 播放按钮
- 疑似/已确认状态
- 家属确认按钮

## 六、隐私与性能

- 服药视频属于敏感健康数据，只允许本人和绑定家属访问。
- 视频需要加密存储，并设置保留期限。
- 香橙派 1.5GB 内存不要跑大型动作模型；录制 720P、动作检测降到 5～10 fps，复杂识别可交后端处理。
- 摄像头正对老人脸部和桌面药盒，避免逆光；录制视频时人脸识别可以降频，但录像保持稳定。

# 无电脑正式使用与 App 注册人脸方案

## 1. 产品阶段的电脑角色

- 生产/初次部署：电脑只用于把系统镜像和程序写入 SD 卡。
- 正式使用：电脑完全断开，设备依靠电源、WiFi、香橙派本地服务和后端运行。
- 固件更新：后续通过 App 触发 OTA，不需要再连接电脑。
- 紧急维护：仍然可以通过 SSH、串口或重新刷卡维护，但不属于日常操作。

## 2. 设备首次配网

1. 香橙派首次启动时若未连接 WiFi，自动开启临时配网热点或 BLE 广播。
2. 手机 App 扫码/选择设备，把家庭 WiFi 名称和密码发给设备。
3. 香橙派连接家庭 WiFi，并向后台注册 `device_id`。
4. 后台生成设备令牌，香橙派保存令牌。
5. 设备通过 MQTT/TLS 或 WebSocket 主动连接后台，保持在线。
6. App 设备页显示：在线、摄像头正常、雷达正常、播报器正常。

## 3. App 注册人脸流程

1. 家属在 App 选择“老人/子女”成员。
2. 点击“注册此设备人脸”，后台创建一次性 `enroll_session`。
3. 后台通过 MQTT/WebSocket 下发：

```json
{"type":"face_enroll_start","session_id":"...","user_id":12,"name":"elder","samples":5}
```

4. 香橙派打开摄像头，并把预览流或连续截图传到 App。
5. App 提示“正对镜头、稍微左右转头、保持光线”。
6. 香橙派本地采集 5～10 帧，检查：
   - 是否只有一张脸
   - 人脸面积是否足够
   - 是否模糊/过暗/过曝
   - 多帧姿态是否足够
7. 香橙派用 YuNet 检测、SFace 提取 embedding，并保存在本地加密文件中。
8. 香橙派只把质量报告、模板版本和一张缩略图回传后台。
9. App 显示注册成功；后台记录该成员的人脸模板版本。
10. 重新注册或删除人脸时，后台通过同一通道通知香橙派撤销旧模板。

### 人脸数据存储原则

- 原始人脸照片只在注册过程中临时使用，不长期保存。
- 香橙派只保存 SFace embedding，并使用设备密钥加密。
- 后台保存用户、模板版本、设备绑定关系和质量报告，不保存可直接还原的人脸照片。
- 用户删除人脸时，本地 embedding 和后台模板记录同时失效。

## 4. App 测试识别

App 设备页提供“测试识别”按钮：

1. App 下发 `face_recognize_test`。
2. 香橙派连续识别 3～5 帧。
3. 返回：

```json
{"identity":"elder","score":0.73,"votes":3,"result":"recognized"}
```

4. App 显示“识别成功/未识别/需要重新注册”，并显示抓拍缩略图。

## 5. 正式识别与播报流程

```text
雷达检测到人
  -> 香橙派抓 3～5 帧
  -> YuNet + SFace 本地识别
  -> 未识别：不播报个人药品
  -> 已识别：user_id + score
  -> 后台查询该用户下一次用药
  -> 检查小智状态
  -> 小智空闲：把播报文本发给 ESP32 -> SYN6288
  -> 小智忙碌：等待 10 秒，超时取消
  -> 本次触发开始服药录像
```

### 播报优先级

1. 小智的 `listening/speaking` 优先。
2. SYN6288 不抢占小智。
3. 小智一旦进入对话，立即停止 SYN6288，并取消待播队列。
4. 同一人在场只播报一次，离开后 30～60 秒才允许下一次。
5. 未识别人员不播报个人药品信息。

## 6. 小智状态来源

优先级从高到低：

1. 小智服务端通过 WebSocket/MQTT 发布 `idle/listening/speaking`。
2. 香橙派通过小智服务端会话状态推断。
3. 麦克风 VAD 仅作为兜底，不作为最终依据。

如果小智服务端无法提供状态，第一版可以先只在“雷达触发时”检查小智 WebSocket 是否活跃；后续再补完整状态回调。

## 7. 服药录像和 App

触发播报后：

1. 香橙派开启 5 秒预缓冲 + 20～30 秒视频录制。
2. 视频默认为无音频，避免录下老人和小智的私人对话。
3. 本地记录服药事件：

```json
{
  "user_id": 12,
  "identity": "elder",
  "recognition_score": 0.73,
  "started_at": "...",
  "video_path": "/home/orangepi/intake_videos/xxx.mp4",
  "status": "possible_taken"
}
```

4. 有网络时上传视频和事件到后端；无网络时本地排队，联网后补传。
5. App 的记录页显示视频、缩略图、疑似/已确认状态。
6. 通过 App 或小智语音确认“已经吃药”后才改为 `confirmed`。

动作识别只作为辅助判断，不能单独作为医疗事实。建议先做“识别到人后录像 + 家属确认”，再增加手拿药、手到嘴边的轻量动作模型。

## 8. 后台数据结构

在现有 `User`、`FamilyLink`、`Medicine`、`Reminder`、`IntakeLog` 基础上增加：

- `Device`：device_id、family_id、token_hash、online_at、firmware_version
- `DeviceCapability`：camera、radar、tts、xiaozhi_state
- `DeviceFaceTemplate`：device_id、user_id、template_version、quality、status
- `RecognitionEvent`：device_id、user_id、score、created_at
- `IntakeEvent`：user_id、reminder_id、video_url、thumbnail_url、status、confidence、created_at

## 9. 通信方式

推荐 MQTT over TLS 或 HTTPS + WebSocket：

- 设备主动连接后台，不需要公网开放端口。
- App 指令通过后台下发到香橙派。
- 香橙派状态、识别结果、录像上传都主动发起。
- 断网时本地任务继续，联网后同步后台。

## 10. 分阶段实施顺序

### 第一阶段：App 注册与本地识别

- 香橙派注册为家庭设备
- App 下发人脸注册任务
- 本地 YuNet + SFace 完成注册和识别
- App 显示测试识别结果

### 第二阶段：雷达与播报

- ESP32 雷达事件通过 WiFi 上报
- 香橙派识别身份
- 后端返回个人用药播报文本
- ESP32 控制 SYN6288 播报

### 第三阶段：小智仲裁

- 小智服务端上报 idle/listening/speaking
- 香橙派增加统一播报状态机
- 小智对话时停止或丢弃 SYN6288 播报

### 第四阶段：服药视频

- 触发后录像
- 后台上传和存储
- App 显示视频和确认状态
- 增加轻量动作识别作为“疑似服药”证据

### 第五阶段：稳定性

- 多人同时出现
- 断网重连
- 摄像头掉线
- 小智长时间对话
- 连续运行 72 小时
